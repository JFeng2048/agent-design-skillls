# 状态更新策略决策表

用于决定「每轮替换」还是「持久追加」。填入实际数值后，用 `../scripts/cache_cost_estimator.py` 计算分界点。

---

## 1. 输入参数

| 参数 | 含义 | 取值来源 |
| --- | --- | --- |
| S | 每条状态消息的 token 数 | 用实际模板 tokenizer 计算 |
| R | 两次更新之间新增后缀的 token 数 | 平均一轮的用户消息 + 工具结果 + 模型输出 |
| N | 预计更新次数 | 任务平均轮数 |
| α | 缓存输入单价相对普通输入的倍数 | 服务商定价（缓存通常更便宜，α < 1） |

## 2. 成本公式

替换：`C_replace ≈ (N - 1) × (1 - α) × R`

追加：`C_append ≈ α × S × N × (N - 1) / 2`

判定：当 `α × S × N / 2 < (1 - α) × R` 时倾向**持久追加**，否则倾向**每轮替换**。

## 3. 快速决策表（定性）

| 场景特征 | 倾向策略 | 说明 |
| --- | --- | --- |
| S 小、R 大 | 持久追加 | 保留旧状态比反复重算长后缀便宜 |
| S 大、N 大 | 每轮替换 | 避免陈旧状态累积与 token 膨胀 |
| 轨迹很长 | 每轮替换 | 陈旧状态的歧义成本随长度放大 |
| 会话短、轮数少 | 持久追加 | 缓存完全友好，实现简单 |
| 小模型、易被陈旧状态误导 | 每轮替换 | 歧义成本高于缓存收益 |
| 要求轨迹完整可审计 | 持久追加 | 只增不改的历史天然可审计 |

## 5. 混合策略选项

| 策略 | 做法 | 适用 |
| --- | --- | --- |
| 分区更新 | 易变字段每轮替换，稳定字段追加一次后固定 | 状态栏字段差异明显 |
| 阈值切换 | 前 k 轮追加，累积超阈值后改为替换 | 轨迹长度不确定 |
| 稀疏替换 | 每 m 轮替换一次 | 更新极频繁但状态变化小 |

## 6. 与压缩的配合

轨迹过长需要压缩时：
1. 确认状态栏覆盖决策所需的全部维度（见 `../references/maintenance-security.md`）。
2. 删除已被状态栏提炼的原始记录段落。
3. 删除只影响被删段落之后的缓存，与更新策略一并测算。
