# Agent 状态栏的构成

状态栏包含三类信息。设计时要逐类回答「放什么」「从哪来」「多久更新一次」。

## 1. 任务规划（TODO 列表）

**解决什么**：处理复杂多步骤任务时轨迹变长，Agent 容易过分关注当前局部子任务，忘记用户原始诉求、核心约束和后续工作。

**做法**：把任务分解为清晰步骤，将 TODO 列表放在**轨迹末尾**，不断提醒模型当前进展与后续目标，确保行动与总体规划一致。

**结构要求**：

| 字段 | 说明 |
| --- | --- |
| 唯一标识符 | 稳定 ID，供 `update_todo_status` 精确引用，避免按序号错位 |
| 内容 | 一句话可验证的目标，动词开头 |
| 状态 | `pending` / `in_progress` / `completed` / `cancelled` |
| 时间戳 | 创建与状态变更时间，用于判断停留时长 |

**认知负荷视角**：TODO 列表起到**外部记忆**作用——就像人处理复杂项目时写清单，Agent 也需要一个地方记录「做了什么、还差什么」。

**效果数据**：启用 TODO 的 Agent 平均 15 次迭代完成任务；禁用时需 21 次且经常遗漏子任务。

**实现要点**：提供 `rewrite_todo_list` 与 `update_todo_status` 两个专用工具（见 `assets/todo_tool_schema.md`）。借鉴 Manus 的「通过复述操纵注意力」理念——每次重写 TODO 都是一次对目标的复述。

## 2. 事件的侧信道信息（Side-channel Information）

**解决什么**：模型理解事件的时序关系与环境背景。

**定义**：不在主要数据通道中传递、但对理解事件很有帮助的**辅助信息**。

**典型字段**：

| 字段 | 用途 |
| --- | --- |
| 精确时间 | 以 `[2025-09-14 10:30:45]` 作为前缀添加到用户消息与工具响应 |
| 距上次 Agent 回复的时间间隔 | 判断是否需要重新确认、是否用户已离开 |
| 地理位置 | 位置相关的服务与合规判断 |
| 事件来源 | 区分真实用户输入、工具结果、框架注入 |

**关键约束**：时间戳**不能放在系统提示词中**，否则每轮改写前缀、破坏 KV Cache。侧信道信息**随对应事件一起追加**。

**附加能力**：实现时间模拟后，Agent 能理解「昨天的文件」与「今天的修改」之间的关系，也让调试与审计有据可依。

## 3. 环境当前状态的观察摘要

**解决什么**：让 Agent 感知「此刻的环境」，而非停留在任务开始时的环境。

**典型字段**：

| 字段 | 说明 |
| --- | --- |
| 系统时间 | 当前时间，随时间推进更新 |
| 工作目录 | 执行 `cd` 后自动更新，确保后续操作在正确上下文 |
| 操作系统类型 | 平台相关决策（Linux 用 apt、macOS 用 brew） |
| Shell 环境 | 命令语法与可用工具 |
| Python 版本 | 语法与依赖兼容性 |
| 异常操作提醒 | 「该工具已被重复调用 N 次」 |

**设计原则**：这一原则同样适用于人类界面——CLI 与 GUI 都致力于让用户清晰感知系统的当前状态。给模型的信息也应如此。

**从隐式到显式**：环境状态往往隐含在工具调用中（`cd` 之后路径变了但没有显式记录）。状态栏的职责就是把这些隐式状态**转换为显式观察**。

## 4. 更新节奏对照

| 类型 | 更新时机 | 位置 | 保留方式 |
| --- | --- | --- | --- |
| 侧信道信息 | 随事件产生 | 随对应事件追加 | 永久留在轨迹中 |
| 任务规划（TODO） | 每步状态变更时 | 状态栏末尾 | 按更新策略替换或追加 |
| 环境观察摘要 | 每轮或环境变化时 | 状态栏 | 按更新策略替换或追加 |

## 5. 字段取舍原则

- 每个字段都要回答「模型缺了它会做错什么决定」。答不出就删掉。
- 计数字段优先：工具调用次数、剩余重试次数、已完成 TODO 数——这些正是模型最不擅长现算的。
- 结论优先：写 `3/3 已达上限`，不写「详见上述记录」。
- 稳定字段与易变字段分开：易变字段（时间）每轮更新，稳定字段（用户原始诉求）不必每轮重复。
- 状态栏总长度受控：它是注意力资源，不是日志。

## 6. 自检

- [ ] TODO 项含唯一 ID、内容、状态枚举、时间戳
- [ ] 时间戳随事件追加，未写入系统提示词
- [ ] 环境摘要含时间、工作目录、OS，工作目录随 cd 更新
- [ ] 含异常操作提醒（重复调用次数）
- [ ] 每个字段都能说明「缺了它会做错什么决定」
- [ ] 计数字段以结论形式呈现（已用/上限）
