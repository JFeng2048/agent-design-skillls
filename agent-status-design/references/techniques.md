# 五种好用的 Agent 状态栏技术

五种技术各自可独立启用或禁用，建议逐步消融验证效果。

## 技术一：时间戳跟踪（Timestamp Tracking）

**做法**：以 `[2025-09-14 10:30:45]` 格式作为**前缀**添加到用户消息与工具响应中。

**注意**：绝不能放在系统提示词中，否则破坏 KV Cache。

**作用**：
- 让 Agent 理解时序关系。
- 为调试与审计提供信息。
- 配合时间模拟功能，Agent 能理解「昨天的文件」与「今天的修改」之间的关系。

**实现要点**：
- 用户消息、工具结果都要加，保持格式统一。
- 可叠加「距上次回复间隔」字段，帮助模型判断对话节奏。

## 技术二：工具调用计数器（Tool Call Counter）

**做法**：维护一个全局字典，记录每个工具被调用的次数，并在响应中标注 `Tool call #3 for 'read_file'`。

**深层价值**：显式计数触发模型的**模式识别**能力——第一次失败后检查路径，第二次失败后列出目录，第三次就主动放弃并寻找替代方案。这实现了**隐式的成本感知**：Agent 能「意识到」自己在某个操作上已尝试太多次。

**实现要点**：
- 计数维度可分层：全局次数 + 按目标分组次数（如 `phone_call(Xfinity): 3`）。
- 计数结果同时写进**工具返回结果**（本次是第 N 次）与**状态栏**（总计 N/M）。
- 用 `scripts/status_ledger.py` 实现统计与约束检查。

**典型收益**：拨打超过 3 次这类约束从「经常违反」变为「稳定遵从」。

## 技术三：TODO 列表管理（TODO List）

**做法**：借鉴 Manus 的「通过复述操纵注意力」理念，提供两个专用工具：

- `rewrite_todo_list`：整体重写列表（任务分解变更时用）
- `update_todo_status`：更新单项状态

每个 TODO 项包含：唯一标识符、内容、状态（`pending` / `in_progress` / `completed` / `cancelled`）、时间戳。

**认知负荷视角**：TODO 列表是**外部记忆**——Agent 需要一个地方记录「做了什么、还差什么」。

**效果数据**：启用 TODO 的 Agent 平均 15 次迭代完成任务；禁用时需 21 次且经常遗漏子任务。

**实现要点**：唯一 ID 是关键，避免模型按序号引用时错位。工具定义见 `assets/todo_tool_schema.md`。

## 技术四：详细错误信息（Detailed Error Information）

**四层结构**：

1. 错误类型与描述
2. 完整参数的 JSON
3. 调用栈信息
4. **针对性的修复建议**（如遇到 `FileNotFoundError` 时建议验证路径、检查工作目录、使用绝对路径）

**效果数据**：启用后，Agent 在错误场景中找到替代方案的成功率从 **60% 提升到 95%**，从盲目重试转变为有针对性地分析和解决问题。

**实现要点**：修复建议必须**针对该错误类型**生成，泛泛的「请重试」无效。建议与错误类型做成映射表由代码填充。

## 技术五：系统状态感知（System State Awareness）

**注入内容**：当前时间、工作目录、操作系统类型、Shell 环境、Python 版本等。

**要点**：
- **工作目录跟踪尤其关键**：Agent 执行 `cd` 命令后自动更新，确保后续操作在正确上下文中执行。
- **操作系统信息**让 Agent 做出平台相关决策（Linux 上用 apt、macOS 上用 brew）。

## 涌现效应

单独使用效果有限，组合起来产生超出预期的效果：

| 组合 | 涌现能力 |
| --- | --- |
| 时间戳 + 工具计数器 | Agent 理解操作的**频率与时间分布**（不只是次数，还有节奏） |
| TODO + 系统状态 | Agent 能根据环境**调整任务策略**（如目录变了就重排步骤） |
| 详细错误 + 工具计数器 | 多次失败后不仅改变策略，还能**理解失败原因** |

完全启用后，Agent 不再是机械执行指令的工具，而更像有自我意识的助手：遇到文件不存在时先检查目录，再列出可用文件，仍找不到就在 TODO 中标记 `cancelled` 并添加替代任务。

这种自适应行为是任何单一技术都无法实现的。

## 两项实用优点

1. **人类可读**：所有元信息以可读形式出现在上下文中，开发者随时可检查 Agent 获得了哪些信息、做了什么决定。
2. **无侵入性**：不需要微调，直接在任何语言模型上都能起效。

## 消融验证建议

| 消融项 | 观测指标 |
| --- | --- |
| 时间戳 | 时序相关问题的正确率 |
| 工具计数器 | 约束遵从率（超限调用次数） |
| TODO | 完成任务迭代次数、子任务遗漏率 |
| 详细错误 | 错误场景找到替代方案的成功率 |
| 系统状态 | 工作目录 / 平台相关操作的正确率 |
| 全部启用 | 思考 token 量、延迟、成本、总体成功率 |

逐步累加，观察单独贡献与组合的涌现增益。
